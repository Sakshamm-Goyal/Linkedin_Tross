# Reverse-engineering notes

## Runtime constraint

The deployed service uses direct HTTP requests only. It has no browser, Playwright, Puppeteer, Selenium, scraping provider, enrichment provider, or official LinkedIn partner API dependency.

Browser developer tools are used only during development to observe requests generated by LinkedIn's own web client. Captured secrets are never committed.

## Observed transports

The current mobile web client uses SDUI/React Server Components at `/flagship-web/rsc-action/actions/component`. The runtime requests the observed `profileCardsAboveActivity`, `profileCardsExperienceOnly`, and `profileCardsBelowActivityPart*` components sequentially.

Responses are line-oriented React Flight/RSC streams, not conventional profile JSON. The shared parser decodes normalized JSON, JSON-LD, metadata, React Flight records, and stable profile loading-state records. If the component set contains no recognizable profile entity, the API fails closed with `UPSTREAM_SCHEMA_CHANGED`.

## Refreshing the RSC contract

1. Sign in to an account you own in LinkedIn.
2. Open developer tools, select Network, and filter for `flagship-web/rsc-action`.
3. Open a consented profile and its detail pages.
4. Confirm the generated profile component IDs and response content types.
5. Replay the corresponding component route using local environment secrets, never copied credentials in source.
6. Update the RSC decoder only against a redacted regression fixture.
7. Run the real smoke test and parser regression suite.

Do not commit copied cURL commands: they commonly contain `li_at`, `JSESSIONID`, CSRF values, tracking identifiers, and account-specific metadata.

## Authentication contract

The direct client sends:

- `li_at` and `JSESSIONID` in the `Cookie` header (or an explicitly configured complete cookie header from the same session);
- the unquoted JSESSIONID value as `csrf-token`;
- `x-restli-protocol-version: 2.0.0`;
- a stable configured user agent and profile referer for the component action.

The service does not automate login, MFA, checkpoints, CAPTCHA, or browser/fingerprint bypass. A direct authenticated account probe, redirects, and authwall markers form the session health contract. Refreshed response cookies are merged into an optional encrypted persistent jar. Authentication failures are briefly cached so repeated callers cannot create a retry storm against a rejected account.

## Parser design

LinkedIn RSC responses contain structured SDUI/React payloads alongside HTML metadata. The parser decodes embedded JSON and direct line-oriented React Flight records, recursively indexes entities, and decodes the stable top-card loading-state records for name, headline, and profile image. It reports every unavailable section explicitly rather than claiming an empty section was observed.

The parser never treats a missing section as proof that a member has no data in that section.
