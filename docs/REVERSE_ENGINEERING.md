# Reverse-engineering notes

## Runtime constraint

The deployed service uses direct HTTP requests only. It has no browser, Playwright, Puppeteer, Selenium, scraping provider, enrichment provider, or official LinkedIn partner API dependency.

Browser developer tools are used only during development to observe requests generated by LinkedIn's own web client. Captured secrets are never committed.

## Observed transport

The current web client uses an SDUI/React Server Components rollout at `/flagship-web/rsc-action/actions/*`. Captured generated components include `profileCardsAboveActivity`, `profileCardsExperienceOnly`, and `profileCardsBelowActivityPart*`.

The runtime directly requests the authenticated profile route and the RSC-backed detail routes for experience, education, skills, certifications, and languages. It decodes JSON, JSON-LD, metadata, and React Flight records embedded in the responses. If the RSC payload no longer contains a recognizable profile entity, the API fails closed with `UPSTREAM_SCHEMA_CHANGED`.

## Refreshing the RSC contract

1. Sign in to an account you own in LinkedIn.
2. Open developer tools, select Network, and filter for `flagship-web/rsc-action`.
3. Open a consented profile and its detail pages.
4. Confirm the generated profile component IDs and response content types.
5. Replay the corresponding profile/detail routes using local environment secrets, never copied credentials in source.
6. Update the RSC decoder only against a redacted regression fixture.
7. Run the real smoke test and parser regression suite.

Do not commit copied cURL commands: they commonly contain `li_at`, `JSESSIONID`, CSRF values, tracking identifiers, and account-specific metadata.

## Authentication contract

The direct client sends:

- `li_at` and `JSESSIONID` in the `Cookie` header;
- the unquoted JSESSIONID value as `csrf-token`;
- `x-restli-protocol-version: 2.0.0`;
- a stable configured user agent and profile referer.

The service does not automate login, MFA, checkpoints, CAPTCHA, or session recovery. The authenticated `/feed/` response, redirects, and authwall markers form the session health contract.

## Parser design

LinkedIn RSC responses contain structured SDUI/React payloads alongside HTML metadata. The parser decodes embedded JSON and React Flight records, recursively indexes objects, identifies a profile/person entity, maps typed position/education/skill/certification/language entities, selects the largest image artifact, deduplicates records, and reports unavailable sections explicitly.

The parser never treats a missing section as proof that a member has no data in that section.
