# Reverse-engineering notes

## Runtime constraint

The deployed service uses direct HTTP requests only. It has no browser, Playwright, Puppeteer, Selenium, scraping provider, enrichment provider, or official LinkedIn partner API dependency.

Browser developer tools are used only during development to observe requests generated by LinkedIn's own web client. Captured secrets are never committed.

## Observed transports

Two profile transports were observed across LinkedIn web-client rollouts:

1. Normalized Voyager GraphQL calls at `/voyager/api/graphql`, including a `voyagerIdentityDashProfiles.<build-hash>` operation.
2. A newer SDUI/RSC rollout at `/flagship-web/rsc-action/actions/*`, with generated profile component IDs such as `profileCardsExperienceOnly` and `profileCardsBelowActivityPart*`.

This repository implements the directly replayable normalized Voyager profile operation because its response contains typed entities suitable for a stable JSON contract. Operation ID and variable name are configuration, not parser constants. If the configured account stops accepting that operation, the API fails closed with `UPSTREAM_SCHEMA_CHANGED`; it does not silently return fabricated or DOM-derived data.

## Refreshing the operation ID

1. Sign in to an account you own in LinkedIn.
2. Open developer tools, select Network, and filter for `voyager/api/graphql`.
3. Open a consented profile URL and find the request whose `queryId` starts with `voyagerIdentityDashProfiles.`.
4. Confirm its `variables` parameter uses either `vanityName` or `publicIdentifier`.
5. Replay the request locally with its sensitive headers removed from terminal history or loaded from local environment secrets.
6. Update `LINKEDIN_PROFILE_QUERY_ID` and, if needed, `LINKEDIN_PROFILE_VARIABLE_NAME` in deployment secrets/configuration.
7. Run the real smoke test and parser regression suite.

Do not commit copied cURL commands: they commonly contain `li_at`, `JSESSIONID`, CSRF values, tracking identifiers, and account-specific metadata.

## Authentication contract

The direct client sends:

- `li_at` and `JSESSIONID` in the `Cookie` header;
- the unquoted JSESSIONID value as `csrf-token`;
- `x-restli-protocol-version: 2.0.0`;
- a stable configured user agent and profile referer.

The service does not automate login, MFA, checkpoints, CAPTCHA, or session recovery. `/voyager/api/me` is the authoritative health check.

## Parser design

LinkedIn normalized responses reference entities by URN and include typed objects in nested `included` structures. The parser recursively indexes objects, identifies a profile entity, maps typed position/education/skill/certification/language entities, selects the largest image artifact, deduplicates records, and reports unavailable sections explicitly.

The parser never treats a missing section as proof that a member has no data in that section.
